## Result

Governance's implemented first-party JWT signing and verification paths use PS256 and RSA keys of at
least 3072 bits. External Access access-token verification and outbound Jump return-token
verification reject other signature algorithms. The repository publishes public PS256 RSA JWKS on
Base App and Base Org and publishes no private key members. This is a repository-side result only;
live Access and Jump gateway compatibility is not verified.

The source audit found the following local JWT paths:

- Auth access tokens and RP state use `JitSecurityJwtKeyring` and the repository registry.
- Preference JWTs use `SecurityJwtPreferenceTokenCodec` and the same key registry.
- OIDC `private_key_jwt` client assertions use `OidcClientAssertionJwt` and the same key registry.
- Governance-to-Jump return tokens use `JumpRtIssuer` and `SecurityJwtJumpRtTokenCodec`.
- Jump-to-Governance return tokens are verified by `JumpRtReturnVerifier` against the gateway's
  public JWKS.
- Access-issued access tokens are verified by `OidcOpAccessTokenVerifier` using the Access JWKS.

No local ID-token or logout-token verification implementation was found in `app/` or `lib/`; the
repository-side Access token verification path is the access-token verifier above. This records the
code inventory and does not claim that an external provider has no additional token behavior.
OpenAPI contains no JWT algorithm declaration to migrate. Discovery and Access-issued ID/logout
token behavior remain with the Access owner.

## Key provisioning and external checks

The deployment owner must provision the Governance source names below with compatible material:

- `AUTH_JWT_PRIVATE_KEYSET`: JSON `kid` map of Base64-encoded RSA PKCS#8 private keys, each at least
  3072 bits.
- `AUTH_JWT_PUBLIC_KEYSET`: matching public RSA PS256 JWKs for current and still-verifiable grace
  keys.
- `AUTH_JWT_ACTIVE_KID`: the active `kid` present in the configured keysets.
- `AUTH_JWT_REVOKED_KIDS`: the shared revoked-`kid` list when revoking keys.

The code validates RSA type, modulus size, algorithm, public-only material, and keypair agreement;
configuration parse errors carry the variable name and do not print key bytes. No real key material
was inspected, created, printed, or changed. `git status --short -- config/credentials` was empty.

Not verified: live Access JWKS or sign-in against Access; Access's OP signing configuration;
production key provisioning; Jump gateway's PS256 registration, acceptance of Governance return
tokens, or its live return-token JWKS. The gateway owner must publish a PS256-compatible key before
production traffic uses the new verifier. These are external owner actions; no fallback algorithm
was added.
