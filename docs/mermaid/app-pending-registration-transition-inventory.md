# APP Pending Registration Transition Inventory

**Accepted (owner, 2026-11-15), design only; not implemented.** Owner: Governance (`app_zenith`).
The lifecycle authority is `client_registrations.status_id`, which references the id-only
`client_registration_statuses` table. Source decision:
[`adr/sign-up-finalization-in-auth.md`](../../adr/sign-up-finalization-in-auth.md#cosmos-split-amendment-governance-owned-pending-registration-2026-11-14).
Diagram: [`app-pending-registration-lifecycle.mmd`](app-pending-registration-lifecycle.mmd).

One named transition writer owns every edge. It locks and reloads the row, uses the `app_zenith`
database clock, rechecks the source state and `deadline_at`, and writes the Chronicle audit outbox
row in the same transaction. Every Access-issued handoff's `jti` receipt is inserted in that same
transaction. Controllers, jobs and callbacks never write `status_id`.

| From                 | To                   | Event               | Entry / writer                                                                                                                    | Guard and committed effect                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| -------------------- | -------------------- | ------------------- | --------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| (none)               | `CREDENTIAL_PENDING` | `start`             | Base App receiver for H1 `registration-start+jwt`                                                                                 | Availability open. Ingress passes: PS256 via Auth JWKS, `iss`, `aud`, `typ`, `exp`, new `jti`, no `sub`/`act`. Eligibility passes: birthdate rule, identifier not active. Halt any pending registration with the same identifier claim or browser cookie. Insert the row with identifier digest, encrypted identifier, birthdate, method, a fresh user handle, `cer` digest, browser secret digest, `deadline_at` and `purge_after`; set the `__Host-` cookie. |
| (none)               | `COMPLETED`          | `start`, `complete` | Same H1 receiver, when the method's requirement set has no Auth credential                                                        | As above, then the completion effects below, in the same transaction.                                                                                                                                                                                                                                                                                                                                                                                          |
| `CREDENTIAL_PENDING` | `COMPLETED`          | `complete`          | Base App receiver for H3 `registration-credential+jwt`                                                                            | Deadline not passed; cookie digest, `cer` and method match. Create the `Client`, effective contact binding or external identity, `ClientPasskey` and `ClientRegistrationCompletion` (`sign_up_flow_ref` = registration public ID) through their owning writers; set `purge_after`.                                                                                                                                                                             |
| `CREDENTIAL_PENDING` | `CANCELLED`          | `cancel`            | Base App receiver for H5 `registration-cancel+jwt`                                                                                | Cookie digest and `cer` match. Releases the claim. No physical deletion. Idempotent.                                                                                                                                                                                                                                                                                                                                                                           |
| `CREDENTIAL_PENDING` | `EXPIRED`            | `expire`            | Any receiver at request time, or `ClientRegistrationExpiryJob` (every five minutes, `FOR UPDATE SKIP LOCKED`)                     | `deadline_at` is at or before the database clock. Request-time expiry is authoritative; the job is a recovery sweep and skips terminal rows.                                                                                                                                                                                                                                                                                                                   |
| `CREDENTIAL_PENDING` | `HALTED`             | `halt`              | H1 receiver (supersession) or H3 receiver (`identifier_taken` after the effective-identifier unique index refuses the completion) | System-only, with a reason code on the audit event: `superseded_by_identifier`, `superseded_in_browser`, `identifier_taken` or `integrity_violation`.                                                                                                                                                                                                                                                                                                          |

Requests that change no state:

| Request                                              | Outcome                                     | Effect                                                                                  |
| ---------------------------------------------------- | ------------------------------------------- | --------------------------------------------------------------------------------------- |
| Known `jti`                                          | `replay`                                    | Nothing is written. A bound browser receives the current answer again with a new `jti`. |
| Cookie or `cer` mismatch, or an unknown registration | `conflict`                                  | Only the `jti` receipt and a refusal event are written.                                 |
| Credential refused by its unique index               | `rejected` (`credential_rejected`)          | The row stays `CREDENTIAL_PENDING`; the receipt and event are written.                  |
| Any handoff for a terminal registration              | `completed` (bound browser) or `not_active` | Nothing changes. Terminal states are absorbing.                                         |

`COMPLETED`, `CANCELLED`, `EXPIRED` and `HALTED` are terminal. `ClientRegistrationPurgeJob` deletes
terminal rows after `purge_after`; that deletion is not a transition. Audit events are kept
separately.
